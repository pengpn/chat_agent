# 前端输入与流式滚动交互

本文记录对话输入框和流式消息列表的两个常见交互问题：输入法误发送，以及流式输出抢占滚动位置。

## 输入法组合输入

中文等输入法输入文字时，用户按 Enter 通常是在确认候选内容。这个 Enter 同样会触发 `keydown`，但此时最终候选内容可能尚未写入 `v-model`。如果只判断 `event.key === 'Enter'`，就会提前发送候选内容之前的文本。

项目通过两个信号识别输入法事件：

- `event.isComposing`：当前是否处于组合输入阶段；
- `event.keyCode === 229`：部分浏览器对输入法按键事件的兼容标记。

只有按键为 Enter、没有按 Shift、并且不处于组合输入时才发送消息。判断逻辑集中在 `frontend/src/lib/composer-keyboard.ts`。

## 流式输出滚动

模型流式输出时，每个增量都会更新消息内容。如果每次更新都无条件滚动到底部，用户向上阅读历史消息后也会被拉回。

当前策略是：

- 用户位于底部附近时继续跟随最新输出；
- 用户主动向上滚动后暂停自动跟随；
- 发送消息、重新生成、切换回答或切换会话时恢复跟随；
- 流式增量使用即时滚动，避免连续平滑动画排队。

是否靠近底部的计算方式是：

```text
scrollHeight - scrollTop - clientHeight <= 80px
```

对应逻辑位于 `frontend/src/lib/scroll.ts`。

测试覆盖组合输入、普通 Enter、Shift+Enter，以及消息列表靠近底部和向上滚动后的跟随状态。
