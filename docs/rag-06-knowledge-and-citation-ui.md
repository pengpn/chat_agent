# RAG 第六阶段：知识库与引用前端体验

这一阶段把已经完成的知识库、摄取状态和引用快照呈现给普通用户。用户不需要理解向量或 Embedding，只需要看懂三件事：

1. 资料有没有处理完；
2. 这次提问查的是哪些知识库；
3. 回答里的依据来自哪一份原文。

## 1. 页面怎么分工

```text
侧栏「知识库」
    │
    ▼
知识库列表 ── 文档列表
  创建 / 重命名 / 删除
  上传进度、处理状态、失败原因、重试、重新索引

对话 Composer
    │
    ▼
选择一个或多个知识库
    │
    ▼
POST messages { knowledgeBaseIds }
    │
    ▼
SSE citations → 回答中的 [n] 和来源面板
```

知识库页面在 `KnowledgePanel.vue`。对话里的选择器和来源面板在 `ChatPanel.vue`、`CitationPanel.vue`。纯展示规则集中在 `frontend/src/lib/knowledge-ui.ts`，方便单测，不把文案判断散落在模板里。

760px 以下桌面侧栏会隐藏，所以对话页头另外提供“知识库”按钮。返回对话、选择已有会话或新建会话时，都会回到对话视图。

## 2. 为什么状态不直接显示后端枚举

后端状态是 `uploaded → extracting → chunking → embedding → ready/failed`。这些词描述的是流水线，不是用户要做的决定。

页面对应关系是：

| 状态 | 用户看到 |
| --- | --- |
| uploaded | 等待处理 |
| extracting | 正在读取内容 |
| chunking | 正在整理段落 |
| embedding | 正在准备检索 |
| ready | 可以引用 |
| failed | 处理失败，并显示 `errorMessage` |

处理中的文档每 2 秒刷新一次列表。失败可以重试，已经可引用的文档可以重新索引。上传使用浏览器上传进度，显示百分比；如果同一知识库里已有相同文件，接口返回已有文档，页面会说明没有重复添加。

## 3. 对话只提交知识库 ID

Composer 把当前选中的知识库 ID 放进 `knowledgeBaseIds`。它不会提交文档正文、页码或相似度。编辑一条历史问题时，选择器会先恢复那条消息当时的知识库，用户可以改范围后再保存。

未选择知识库时，输入区写明“本次只根据对话回答”。选中后，芯片和说明文字一起标出检索范围。用户消息发出后，气泡上方也会保留“检索范围：……”，包括知识库后来被删除时的“已删除的知识库”。

单次最多选择 8 个，与服务端 `RAG_RETRIEVAL_MAX_KNOWLEDGE_BASES` 的默认限制一致。

## 4. 引用标记和来源面板

流式事件顺序仍是 `delta → citations → done`。前端在 `citations` 事件到达时先挂到正在生成的回答上，`done` 里的完整消息会再次带上同一份快照。刷新页面后，消息接口预加载的 `citations` 用来还原同一面板。

正文里的 `[1]` 只有在这份快照中真实存在时才变成按钮。代码块里的 `[1]` 保持原样，避免把示例代码误当成引用。

来源面板展示：

- 引用编号
- 文档名
- 页码和章节
- 当时保存的原文片段
- 原文仍存在时的下载按钮

如果知识库或文档已经删除，外键会是空的，面板改为说明“原文文件已删除，以下内容是回答当时保存的片段”。下载失败会留在面板里显示错误，不把片段清掉。

键盘操作：Escape 关闭；方向键、Home 和 End 在编号之间移动。移动端面板铺满屏幕，编号按钮和关闭按钮保持 44px 点击区域。

## 5. 怎样验证

```bash
cd frontend
npm test
npm run build
```

单测覆盖状态文案、检索范围说明、已删除来源不可下载，以及引用编号不会改写代码块。
