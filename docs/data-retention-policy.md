# 用户数据保留与删除策略

本文定义 Agent Workspace 当前版本的数据生命周期边界。它是工程实现基线，不替代部署地区要求的隐私政策、用户协议或法律评审。

## 1. 数据分类与默认保留期

| 数据 | 正常使用期间 | 注销账户后 | 实现位置 |
| --- | --- | --- | --- |
| 用户资料、密码哈希 | 账户存续期间 | 立即删除 | `users` |
| 对话、消息、摘要版本 | 账户存续期间 | 通过外键级联立即删除 | `conversations`、`messages`、`conversation_summary_versions` |
| 附件元数据与分块 | 账户存续期间 | 立即删除 | `attachments`、`attachment_chunks` |
| 附件原文件 | 账户存续期间 | 注销流程中删除 | MinIO/S3 |
| Refresh Token 哈希与设备会话 | 有效会话至过期；已撤销会话默认保留 30 天 | 立即删除 | `auth_sessions` |
| 邮箱验证/密码重置 Token 哈希 | 过期后清理；已使用记录默认保留 30 天 | 立即删除 | `account_tokens` |
| 账户安全审计 | 默认 365 天 | 去标识化保留至期限届满 | `account_audit_logs` |
| 应用日志 | 默认 30 天 | 按日志轮转策略清理 | `LOG_RETENTION_DAYS` |

安全审计只保存内部 UUID、事件、时间、User-Agent 和非敏感元数据，不保存邮箱、密码、原始 Token 或对话正文。`AUTH_CREDENTIAL_RETENTION_DAYS` 控制已撤销/已使用凭据记录的保留天数，过期凭据直接清理；`ACCOUNT_AUDIT_RETENTION_DAYS` 控制审计保留天数。应用启动时执行上述清理。

## 2. 账号注销顺序

1. 再次验证当前密码，并要求输入固定文本 `DELETE`。
2. 查询当前用户拥有的全部对象存储 Key。
3. 删除 MinIO/S3 原文件；任一文件失败时中止数据库删除，以免对用户宣称已删除但仍保留原文件。
4. 写入不含个人正文的 `account.deleted` 审计事件。
5. 删除 `users` 记录，依赖数据库外键级联删除业务数据和凭据。
6. 清除浏览器 Refresh Cookie 与本地 Access Token。

对象存储和 PostgreSQL 无法参与同一个 ACID 事务。当前实现选择“隐私优先”：文件未删干净时不删除账户记录，用户可重试。生产环境应增加删除任务表、幂等后台清理和失败告警，形成可恢复的 Saga。

## 3. 个人数据导出

导出文件包含用户资料、对话、消息、附件元数据、摘要版本和安全审计记录；不会包含密码哈希、Refresh Token 哈希、一次性 Token、对象存储内部 Key或文档提取的内部缓存。附件原文件当前不打包进 JSON，后续可使用短期签名下载链接或异步压缩包实现。

## 4. 备份与生产部署补充

- 数据库/对象存储备份可能在注销后继续存在至备份自然过期；生产隐私政策必须明确备份周期和恢复后的二次删除流程。
- 邮件供应商、模型供应商和日志平台属于独立处理方，应根据其协议设置保留期限。
- 生产环境应定期运行审计和过期 Token 清理任务，而不只依赖应用启动。
- 任何延长保留期或新增采集字段都需要同步更新本文件、用户隐私说明和导出范围。
