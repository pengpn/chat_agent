# Chat 页面规范

本文件仅定义对话工作区的页面级规则；未明确覆盖的内容全部继承 `../MASTER.md` 和 `../COMPONENTS.md`。

## 页面目标

让用户把注意力放在任务、上下文和回答上。侧栏负责工作空间导航，主区负责阅读，Composer 负责发起下一步；三者层级清晰但不互相争抢。

## 桌面布局

- App Shell：`272px + minmax(0, 1fr)` 两列，视口高度使用 `100dvh`。
- 侧栏：深色固定导航层，内部列表独立滚动。
- 主区：Header / Messages / Composer 三行网格，中间消息区独立滚动。
- Header：水平内边距允许 `clamp(22px, 5vw, 78px)`。
- Messages 与 Composer：共同使用最大宽度 850px，水平留白保持对齐。
- Composer 位于底部视觉锚点，不使用重阴影模拟悬浮。

## 移动布局（≤760px）

- 当前阶段隐藏桌面侧栏；后续增加移动导航时必须提供明确的会话入口，不能永久牺牲导航能力。
- 页面水平边距 14–18px。
- 输入控件字体至少 16px，点击区域至少 44px。
- 模型菜单宽度为视口减 44px，并校正到 Composer 左边缘，禁止横向溢出。
- 用户消息宽度可扩展到 100%。

## 内容层级

1. 当前对话标题与模型状态
2. 消息正文和附件
3. 回答版本、重新生成等次要操作
4. Composer 与当前输入状态

模型状态在 Header 中只做只读提示；真正的模型切换发生在 Composer 中，避免出现两个可操作入口。

## 流式状态

- 正在生成的内容保持阅读位置稳定，不让 Spinner 替代已经到达的文本。
- 用户上滚后停止自动跟随；回到底部时恢复。
- 中断、超时和错误信息靠近 Composer 或对应消息，并提供重新生成路径。
- 思考内容和正文分别渲染；正文是最终视觉主层级。

## 页面验收

- 两个滚动区域不会互相抢夺滚轮/触摸事件。
- 第二条及后续回答可正常滚动到。
- 中文输入法组合期间 Enter 不发送。
- 模型选择器在桌面向上展开，在 375px 不越界，并支持 Escape。
- 附件、模型选择器和发送按钮在窄屏不重叠。
